# Architecture

Perception Media Editor is a native Apple Silicon macOS app built with SwiftUI and AppKit, Core Image for photo rendering, and AVFoundation for its existing video timeline/playback engine. Development follows the photo-first roadmap.

## Core rule

Original media is never modified. A `.pmedit` project stores references to the originals plus adjustment metadata. Preview and export reconstruct the result from those instructions.

## Current modules

- `EditorNavigation.swift`, `EditorShell.swift`, `VideoExportWorkspace.swift` (editor redesign, Part 1): the app has two categories, Photo (Import, Cull, Develop, Export) and Video (Import, Cut, Export), shown by `CategoryBar` and `StepRail`; Agents opens from both and returns to the previous step. `Workspace` stays the single navigation state; `Workspace.category` and `Workspace.isVideo` classify screens, and `EditorStore.requestCategoryChange`/`requestStepChange` navigate (category and step requests are deferred; openAgents/closeAgents, Library double-click, ingest and new-project writes are synchronous). Each Import step is `LibraryWorkspace` with the import actions in its header; each Import step requests its Library section (Video, or Photos) through the one-shot `libraryEntrySection`, set inside the deferred task; the Library step is remembered per category. Photo Export is `ExportWorkspace`; Video Export is `VideoExportWorkspace` with inline Format and Size pickers, a prominent Export Timeline button, progress and a reveal button. Menu steps switch to their owning category. Autoplay of a finished timeline rebuild is skipped unless a video screen is showing (`beginAutoplay`). Playback pauses on leaving the video screens (Cut to Export keeps playing) and when the category changes. The Workspace menu lists both categories' steps with Command-1 to Command-7 (`EditorStepShortcut`) and Agents on Command-0 (`EditorStepShortcut.agentsKey`), so added steps never collide with it.
- `EditorModels.swift`: versioned project, media, adjustments, crop, and preset data.
- `ProjectDocument.swift`: atomic JSON project persistence and schema guard.
- `EditorStore+Project.swift`: explicit save state and shared manual/autosave persistence; failed saves preserve the last-saved snapshot and expose retry/Save As recovery.
- `ExportFileSafety.swift`: original-file protection by canonical path and device/inode identity, plus temporary-sibling rendering and atomic final output publication.
- `BatchExport.swift`, `EditorStore+Export.swift`, and `ExportWorkspace.swift`: validated batch JPEG settings, stable project-order selection, unique output planning, sequential export state, progress/cancel, and per-file results. Batch publication creates a completed file only if the destination is still unused, so a late collision cannot overwrite a deliverable.

Batch queue verification can inject a file-level asynchronous exporter through `EditorStore` initialization. The app's default uses one sequential `PhotoRenderer` with a 128 MiB allocation target for ordinary exports. Active healing uses a lazy 256 MiB context for full-resolution focus/export; export completion, focus exit, memory pressure and cache/project cleanup clear and release that alternate context. The shared adjustment graph and RAW precision remain unchanged. Disposable fixture tests pause after the atomic publisher writes its temporary JPEG to verify mid-file Stop cleanup, continuation after a real missing-source failure, same-project reopen identity, late callbacks, and replacement-queue ownership. These checks establish queue boundaries, not RAW render speed or photographic quality.
- `PhotoUndoHistory.swift`: changes for affected assets, with one 100-step / 32 MiB estimated retention budget shared by undo and redo. Accounting includes curve points, brush/correction points, subject/sky PNG bytes, and healing/clone points. Session history also has a 16 MiB estimated shoot-wide budget; these budgets do not measure total resident memory.
- `PhotoRenderer.swift`: an actor that renders previews (working copies in GPU-shared half-float pixel buffers, one edited RAW variant per photo, one full-resolution buffer for the 100% view), histograms, thumbnails, and exports off the main thread. Editing uses a working copy capped at 2560 px (RAW files decode through `CIRAWFilter` at reduced scale into a linear half-float buffer), and only four working copies stay in memory. Full-resolution decodes are reserved for 100% focus and export. RAW thumbnails use the camera's embedded JPEG preview.
- `MediaColorRenderer.swift`: shared Core Image adjustment graph used by photo rendering and timeline clip playback.
- `EditorStore.swift`: main-actor application state and file-panel workflows. Preview requests collapse while a render is in flight, so slider drags render only the latest values. Unsaved changes are tracked against the last saved project and confirmed before New, Open, and Quit.
- Workspace views: Library, Cull, Photo, Video, Export, and Agents.
- `HistogramView.swift`: accessible RGB histogram rendered from the edited image pipeline.
- `PhotoComparisonView.swift`: original, edited, split, and side-by-side presentation modes.
Develop preview completion is bound to the project generation, selected asset and source URL. Project replacement cancels the old preview but retains its worker slot until it drains, so repeated opens cannot queue multiple render workers. Requests during that drain coalesce into one render using current edits and mask-overlay selection. A canceled completion cannot publish original/edited images, overlay or histogram into the reopened project. Tests inject a paused preview operation to verify same-ID reopening, relinking and empty-project reset without timing assumptions. This ownership guarantee does not establish the cause of every blank-canvas observation. `PhotoPreviewDiagnostics.swift` provides opt-in local OSLog metadata at renderer/store/canvas boundaries. Disabled tracing does not evaluate its message payload or perform extra pixel reads; enabled tracing uses the existing histogram and does not change rendering, publication or retry behavior.

- `LocalMasks.swift`: the mask model (linear, radial, brush, subject, and sky shapes, each with its own adjustments) and the renderers that turn a mask into a grayscale image. Gradients are procedural and eased in linear light. Brush strokes are painted as soft dabs (lightest-wins for painting, darkest-wins for erasing) and cached, and painting continues from the previous raster so a stroke costs a few milliseconds however many strokes exist. Subject and sky masks are bounded grayscale PNGs with cached decode and the same brush correction path. Edge shift, feather, and contrast refine the corrected mask on this bounded raster before scaling to the photo; shift and feather are stored as fractions of its longer side. Masks are stored in the original photo's coordinates.
- `ImageGeometry.swift`: maps positions between the original photo and the finished picture (rotation, straighten, crop), sharing its crop math with `MediaColorRenderer`. Verified against real renders, since the mask handles and the pixels must agree.
- `EditorStore+Masks.swift`, `MaskEditingLayer.swift`, and `MaskPanel.swift`: mask creation and editing, the handles and brush cursor drawn over the photo, and the panel.
- `SubjectAnalyzer.swift`, `EditorStore+Subjects.swift`, and `SubjectPickingLayer.swift`: analyze an oriented photo with Vision's person and foreground instance requests on a separate actor, select an instance from a click or the list, and persist its soft mask in the project. `SubjectGroupRecovery.swift` checks actual mask coverage at small detected human centers and processes up to three missing areas with sequential crop segmentation. These supplemental candidates are named “People in area” because nearby people can share a crop. Their raster masks preserve schema 10; their picking labels override coarse native labels only within recovered coverage. The overview is the maximum of the retained candidate masks, merged incrementally to bound memory. Hover previews are debounced, guarded against stale completion, and cached with a four-overlay limit. Source-to-finished geometry keeps selections and previews aligned through rotation and crop.
- `SkyAnalyzer.swift`, `SkyEdgeRefiner.swift`, and `EditorStore+Sky.swift`: load the bundled DETR semantic segmentation model lazily on a separate actor, identify its exact sky class from model metadata, and detect sky across the complete oriented frame. Input is 448 × 448; a luminance-guided filter refines its coarse boundary on a raster capped at 1536 px. `SkyBranchRecovery.swift` can add similar blue gaps in model-labeled tree regions near the existing blue-sky band, requiring confirmed sky color anchors. It cannot create sky without semantic sky labels; the maximum with the original guided result preserves previous coverage. This is a bounded color recovery with documented photographic limits, not new model inference. `SkyForegroundExclusion.swift` optionally runs one native foreground request when semantic person evidence exists. It subtracts only high-confidence coverage of instances whose area is at least 60% semantic person, preserving uncertain boundaries and excluding foreground trees from this correction. Auxiliary failure retains usable sky; cancellation propagates, temporary native resources drain in an autorelease pool, and no new application-owned cache is retained. This correction affects newly generated rasters; existing saved masks stay unchanged. The PNG is saved in the project and uses the shared subject correction and rendering path. Canceling, navigating, or switching tools invalidates the request before it can create an edit. Inference uses CPU/GPU locally; no photos are uploaded. The pinned model download is hash-verified by `scripts/prepare-sky-model.sh`, with attribution and license bundled under `Resources/ModelNotices`.
- `Retouch.swift`, `EditorStore+Retouch.swift`, `RetouchEditingLayer.swift`, and `RetouchPanel.swift`: photo-specific heal and clone strokes. Clone translates a sampled patch; heal retains its detail while matching low-frequency color to the destination. Both use soft brush coverage in original-image coordinates and render before geometry and global adjustments.
- `WhiteBalanceEyedropper.swift` and `WhiteBalancePickingLayer.swift`: translate a click through crop, rotation, and EXIF orientation to the RAW decoder's native neutral point. The decoder returns Kelvin and tint values, which are saved as ordinary RAW settings and remain compatible with the existing sliders, presets, and export path.
- `RawSettings.swift`: the settings that belong to the RAW decode (white balance, noise reduction, sharpness, detail, lens corrections), what the engine reports for a file, and white balance presets. Changing one re-decodes (about half a second on a 24 MP S5 file); every value is optional, so an untouched photo stores nothing.
- `ColorGrading.swift` and `HSLColorKernel.swift`: the tone curve (monotone cubic through user points, per-channel, sampled 1024 times for Core Image) and HSL (eight bands blended smoothly). HSL runs as an exact per-pixel Core Image color kernel compiled at run time from kernel-language source, for photos and video alike; a 48-point color cube is kept only as the fallback if the kernel cannot compile. Both act on gamma-encoded color and are skipped when untouched so highlights keep their headroom.
- `AdjustmentGroups.swift`: the Develop panel's groups, and everything built on them: presets, copy/paste/sync, history entries, and preset files.
- `EditorStore+Develop.swift`: RAW info, white balance actions, and the 100% view.
- `AutoAdjustmentAnalyzer.swift` and `EditorStore+Auto.swift`: a separate actor decodes an as-shot preview at 512 px, identifies consistent neutral-color evidence, and fits bounded tone suggestions through the existing renderer using 64 px samples. Tone follows the visible crop. RAW WB uses the decoder's camera calibration; other formats use warmth/tint. Auto replaces only basic light/WB controls as one named history step, keeps other edits, and rejects canceled or stale completions. Repeated Auto analyzes the same source baseline. Values save/export as ordinary adjustments in schema 10.
- `EditorStore+Presets.swift`: applying presets to a selection as one undo step, user preset management, copy/paste/sync, history, and preset import/export.
- `FocusLoupeView.swift`, `ToneCurveEditor.swift` (also the HSL panel), and `PresetPanel.swift` (also the save-preset and copy-settings sheets).
- `IngestService.swift`: card-to-shoot copy. Streams each file to `name.partial` while hashing it, flushes, reads it back without the file cache, compares, then renames into place. Skips a file already present (same name, size, and timestamp, or same content), gives a different file with a colliding name a `-1` suffix, and mirrors to an optional backup. The card is only read.
- `EditorStore+Ingest.swift`: shoot folder layout, remembered locations, and the import flow that fills the project as files arrive.
- `EditorStore+Culling.swift`: capture-ordered visible photos, filters, selection, rating/flag/label commands, key handling, remove, Delete Rejected, and autosave.
- `CullingModels.swift`: flag, color label, filter, and the Lightroom key map.
- `CullPreviewCache.swift`: six screen-sized previews kept around the current photo; at most two decodes in flight, with stale queued work replaced on navigation. RAW files use the camera's embedded JPEG (about 15 ms each).
- `CullWorkspace.swift` and `ImportSheet.swift`: the loupe, compare view, filmstrip, filter bar, and import dialog.
- `ThumbnailCache.swift`: stable, adjustment-aware JPEG thumbnails in Application Support and one 32 MiB LRU memory budget shared by photo/video thumbnails. The store publishes completion revisions instead of retaining duplicate image dictionaries.
- `UserPresetRepository.swift`: persistent user presets backed by app preferences.
- `VideoMediaService.swift`: AVFoundation metadata (duration, size, exact frame rate and count, source color) and poster-frame extraction.
- `SourceColor.swift`: what a video file's code values mean. It reads the camera's own metadata (Lumix files tag V-Log as BT.709 but name it in `com.panasonic.Semi-Pro.metadata.xml`) plus range, matrix, bit depth and chroma from the format description and codec configuration.
- `CubeLUT.swift`, `LUTLibrary.swift`, `LUTKernel.swift`, `LUTControls.swift`, `EditorStore+LUTs.swift`: `.cube` LUTs. The parser validates 3D and 1D tables. Imports are copied into a content-addressed library (Application Support) and, on save, next to the project in `LUTs/`; sources are only read. `LoadedLUTs` holds parsed tables for every renderer, and a missing LUT is reported and skipped. One Core Image kernel applies them with tetrahedral interpolation, a domain and an intensity: as a creative LUT on photos and clips (sRGB-encoded, after the global adjustments), and as a clip's source color in the compositor, on the decoded code values before anything treats them as Rec. 709. With a source-color LUT, the source viewer also plays through the compositor.
- `TimelineExporter.swift`, `EditorStore+TimelineExport.swift`: timeline export. The exporter reads the composition at export quality (originals only) through the export compositor as 10-bit 4:2:2, writes ProRes 422 HQ or HEVC Main10 tagged Rec. 709 with mixed audio to `<name>.partial.mov`, and renames it into place when complete. One export at a time; the proxy queue pauses meanwhile.
- `ScopeTap.swift`, `ScopeRenderer.swift`, `ScopeModel.swift`: video scopes. While the panel is open (`EditorStore.scopesVisible`, which also forces playback through the compositor), the compositor downsamples about every second preview frame to a 512-wide capture; `ScopeRenderer` builds a luma or RGB-parade waveform and a BT.709 vectorscope with Metal atomics on its own command queue, off the main actor, and the panel shows the images.
- `MetalShaderSources.swift`, `MetalPipelineCache.swift`, `VideoColorKernels.swift`: the video color GPU runtime. Shaders ship as strings and compile at first use, because the Command Line Tools have no `metal` compiler. Kernels convert 8/10-bit bi-planar Y'CbCr to unclamped half-float R'G'B' (explicit range, matrix and chroma siting), encode back to video-range 10-bit 4:2:2 for export, and fit a frame to the render size. The custom compositor uses them for every frame.
- `OCIOColorKernels.swift`, `OCIOGeneratedShaders.swift` (generated by `scripts/ocio/generate-shaders.py`; never edited by hand): OpenColorIO's camera input transforms (V-Log/V-Gamut, and iPhone Apple Log/BT.2020) to scene-linear Rec. 709 and its ACES 2.0 SDR 100 nits Rec. 709 view, as Metal source plus lookup tables (base64 float32; Apple Log's is a 2D table sampled linearly), compiled at first use into a library of their own. OCIO itself is not linked ([decision](decisions/2026-10-17-ocio-generated-shaders.md)); the BSD-3 notice ships in `Resources/ThirdPartyNotices`.
- `VideoCompositorDiagnostics.swift`: "VideoCompositor" signposts (an interval per frame, a "GPU" event with its GPU time), per-frame GPU time in the compositor's counters, and opt-in log lines (`PME_VIDEO_DIAGNOSTICS=1`).
- `AudioWaveformService.swift`: asynchronous PCM peak extraction with stable memory and Application Support disk caches.
- `TimelineCompositionService.swift`: translates persistent V1/A1 clip metadata into a playable AVMutableComposition and reports recoverable media warnings.
- `VideoWorkspace.swift`: composes the video screen (media bin, viewer, inspector, timeline).
- `VideoParts.swift`: shared `VideoMediaBin`, `VideoViewer` (transport and optional scope panel) and `VideoTimeline` (persistent V1/A1 controls).
- `AgentModels.swift`, `AgentEngine.swift`, and `AgentWorkspace.swift`: local-first workflow agents with reviewable findings and reversible adjustment proposals.
- `scripts/agent-review.sh`: deterministic developer reviewers for workflow, renderer, schema, compatibility, and release checks.

Photo geometry is stored as optional normalized crop data for backward-compatible `.pmedit` loading. Preview zoom and pan are view state, while crop, straighten, and adjustment history remain non-destructive project edits.

## Autosave

A project that has a file on disk saves itself 1.5 seconds after each change, and immediately before New, Open, or Quit. Only a project that has never been saved asks whether to save.

Save errors persist separately from general status messages until a successful retry, Save As, or project replacement. New/Open and Quit are gated while a card import is running. Each import owns an operation identity and project generation; replacement invalidates queued callbacks, and a subsequent import waits for a cancelled copy worker to finish cleanup. The final verified-file result is reconciled before autosave. Reference-file imports retain their originating generation too.

## Project format

The first project format is readable JSON with the `.pmedit` extension. It stores absolute reference-file URLs. Missing originals can be relinked without changing asset identity or losing adjustments. Every format revision increments `schemaVersion`; newer unsupported versions fail explicitly.

Schema 7 adds healing/clone strokes, schema 8 subject masks, schema 9 subject edge refinement, and schema 10 sky masks. Schema 8 subject masks decode with neutral edges. The integration candidate retains schema 10 and the existing persisted representation; it adds no schema. Older projects remain readable, while applications supporting an earlier schema cannot open newly saved schema-10 projects. The app bundle declares `com.perceptionmedia.project` as a JSON-compatible `.pmedit` type. Test on a project copy when comparing with an older build.

Preview thumbnails are disposable cache files, not project data. Their keys include the asset identity, source path, source modification date, and adjustment metadata, so stale renders are not reused.

## Video playback boundary

V0.3 stores non-destructive `TimelineClip` records separately from source media. Per-clip entries in `videoAdjustmentsByClipID` reuse `PhotoAdjustments`, so the same light, color, presence, and preset values persist for photos and timeline clips. Clip timing is whole frames (schema 11), and `TimelineCompositionService` builds every time exactly from frames at the sequence timescale ([decision](decisions/2026-10-16-frame-exact-timing.md)). It translates clip records into an `AVMutableComposition`. Plain Rec. 709 clips of one size and orientation play through AVFoundation as they are. Anything else (a grade, V-Log footage, a proxy, a mixed size or orientation) attaches a custom `AVVideoCompositing` compositor with one instruction per clip and black instructions over gaps; see "Custom compositor" below. The store owns playback state, playhead synchronization, and automatic active-clip selection; missing or incompatible clips are skipped with visible warnings.

### Custom compositor

`TimelineVideoCompositor.swift` (with `TimelineCompositionInstruction.swift`, `ColorGradeStage.swift`, `VideoTexturePool.swift` and `SourceOrientation.swift`) renders the timeline's pictures. `PreviewVideoCompositor` answers in half-float `64RGBAHalf` and `ExportVideoCompositor` in video-range 10-bit 4:2:2 (`x422`), so preview quality is chosen by the class set on the `AVVideoComposition`. It asks AVFoundation for every bi-planar 8/10-bit Y'CbCr format (never 32BGRA) and per frame does: decode on Metal (`VideoColorKernels`), turn upright and fit to the render size (one fit kernel applies each clip's `preferredTransform` and handles mixed sizes), grade with the photo color graph in Core Image on the same command buffer (`MediaColorRenderer`), then write the output (or encode `x422`). A neutral, upright clip already at the render size decodes straight into the output frame. Requests run on a private serial queue with at most two frames on the GPU; `cancelAllPendingVideoCompositionRequests` bumps a generation and waits until every request is answered. Frames are tagged with Apple's `CoreMedia709` color space for Core Image, which is what AVFoundation used under the old CIFilter handler: tagging them ITU-R 709 instead moved a graded frame by 10 of 255 levels. Source color comes before the grade: a source-color LUT maps the decoded code values; OpenColorIO's path runs the V-Log input transform into scene-linear Rec. 709, grades there in Core Image's own linear working space, and applies the ACES 2.0 output transform last (one fused kernel when there is nothing to grade). If the OCIO shaders do not compile, the composition warns and V-Log shows as recorded. Working textures come from a bounded pool. Memory pressure empties the pool and CoreVideo's texture cache, clears Core Image's caches and drops the scope captures. A timeline gap is a black instruction; AVFoundation delivers it as one frame lasting the whole gap. The source viewer plays through the compositor whenever the clip has a source color to apply or the scopes are open.

Per-clip entries in `audioAdjustmentsByClipID` persist volume, pan intent, fade-in, and fade-out without modifying source media. Timeline playback applies volume and fade ramps through `AVAudioMix`. Pan is reserved in the model but intentionally deferred until a custom audio-processing tap can implement it accurately. Waveform peaks are extracted at a reduced mono sample rate, normalized for display, and cached by source path, modification date, and sample count.

The current sequence uses the first playable clip's preferred transform. The color render layer deliberately excludes photo crop and rotation metadata; per-clip mixed-orientation fitting remains future work.

## Memory management

Photo rendering uses half-float linear working sources to preserve RAW highlight headroom.
Core Image allocation targets are 256 MiB for editing, 128 MiB for ordinary focus/export, a lazy 256 MiB context for active full-resolution healing, and 32 MiB for thumbnails. These are targets rather than process-wide caps. Synchronous
render operations drain autoreleased intermediates before returning. Closing 100% focus,
completing or failing an export, and replacing the project clear expendable context caches.
A macOS memory-pressure observer drops thumbnail, culling, brush, and decoded selection/subject-preview caches, trims the working
source cache, and clears renderer resources while preserving the visible image and project.

Auto uses one UI control beneath the histogram and the advanced tone/WB analyzer. Its task is owned by the store, cancellation is checked before analysis and between fitting passes, and completion checks operation identity, project generation/ID, source URL, and the initial edit snapshot. Undo/redo, manual edits, navigation, and tool changes cancel pending Auto. Analysis uses a 128 MB Core Image allocation target and clears render caches when finished; this is not a whole-process memory cap.

Culling cancellation is cooperative: a RAW decode already inside a synchronous system call
keeps its concurrency slot until it returns. Cancelled and removed requests cannot repopulate
the cache. A failed decode is not automatically retried forever. Compare and neighborhood
requests are submitted together so the comparison image is not cancelled by prefetching.

Use `scripts/profile-memory.sh` for an isolated real-RAW footprint/latency/pixel comparison.
Set `PME_RAW_SAMPLE_DIR` to a folder of at least four RW2 files. Measurements include compressed
and graphics memory charged to the process; they are not a whole-app memory ceiling.

Workspace picker writes use a coalesced main-actor transition after SwiftUI finishes its native view update. Direct model/menu navigation stays synchronous and cancels queued picker work. Project replacement also cancels it, preventing old UI navigation from changing a newly opened project.
